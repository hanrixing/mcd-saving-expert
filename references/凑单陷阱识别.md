# 凑单陷阱识别

> 用真实价格证伪"先涨后降"和"凑单更贵"。涉及套餐/凑单的问题必读。

---

## 核心前提

外卖"感觉变贵了"是真实的结构性变化，但**具体某单有没有被套路，必须用数据说话，不能靠猜**。

本项目的优势：麦当劳 MCP 的 `query-meals` + `query-meal-detail` + `calculate-price` 能拿到**官方真实价格构成**，用数据证伪套路，而不是罗列行业黑话。

---

## 一、套路一：先涨后降

### 识别方法

用 `query-meal-detail` 查单品原价，用 `query-meals` 查套餐价，比对：

```
单品甲 × 1 = A 元
套餐（含甲+乙+丙）= B 元，且"满 B 减 D"

推论：套餐里的甲实际上被抬价了
单点甲+单点乙+单点丙 = A + C + E
对比 B-D 与 (A+C+E)
```

**若套餐"折后价"高于单点总价 → 存在凑单溢价**

### 正确话术

> 我查了一下：巨无霸单点 ¥A，麦辣鸡腿堡单点 ¥C，可乐 ¥E，三样单点合计 ¥(A+C+E)。
> 但"超值套餐"标价 ¥B 减 ¥D，到手 ¥(B-D)。
> **套餐比单点贵 ¥差额**，主要贵在凑单的饮品和薯条——如果你本来只想吃汉堡，单点更划算。

**要点**：给数字，不给结论。用户自己判断。

---

## 二、套路二：凑单更贵

### 识别方法

凑单品的典型特征：低单价、高利润率、和你需求无关（可乐、薯条、甜品）。

用`query-meals` 查门店实际在售商品，找出套餐里"你可能不需要"的部分：

```
套餐到手价¥F
减去你真正想吃的部分 ¥G
= 你为凑单多付的 ¥(F-G)
```

### 核心问题（一句话问用户）

> **"这个凑单商品，你本来会买吗？"**

答案是否 → 直接建议单点，不要凑。

### 正确话术

> 这个套餐里有薯条和可乐。你要吃的是汉堡对吧？
> 如果去掉凑单部分，单点合计更便宜。建议单点。

**不要**为了凑券门槛而推荐买不需要的东西。这是帮倒忙。

---

## 三、折扣券的真实价值验证

`calculate-price` 会算出优惠后的应付总额，用它验证券是否真省：

```
标价 ¥B，满减 ¥D，可用券 ¥C
实际应付 = B - D - C + 配送费
```

**判断**：如果省的钱 ≤ 配送费，那么"用券"其实不省——因为门槛通常会诱导你多买东西。

---

## 四、不做的事

1. **不用"行业都是这样"来指控麦当劳**——本项目只做价格事实对比，不做动机推断
2. **不给"维权/投诉"建议**——超出本项目范围
3. **不拿不同门店价格作对比**——不同店定价本就不同，会误导用户

---

## 五、纪律

- 所有价格必须来自 MCP 实时查询，不引用历史经验数字
- 比价必须**同门店、同时间、同一商品**，否则无意义
- 发现确实更贵的组合，如实告知，但**不夸大、不引导用户觉得被坑**
- 本项目只解决"怎么点更划算"，不评价商家诚信
